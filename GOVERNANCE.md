## Decision Making

- **Small changes** (bug fixes, docs, minor improvements): Maintainer decides, no formal process needed
- **Significant changes** (new features, API changes, license changes): Discussed via Issue or QQ group before implementation
- **Breaking decisions**: Require explicit approval from at least one maintainer

## Becoming a Maintainer

Currently, there is no formal process. Contributors who demonstrate:

- Consistent, high-quality contributions
- Understanding of project goals and architecture
- Good communication with the community

may be invited by the current maintainer.

## Code Review

All changes go through Pull Request review. At least one maintainer must approve before merge.

## License Changes

Any change to the project's dual-license structure (MIT for `api/`, AGPLv3 for core) requires explicit discussion and consensus.
